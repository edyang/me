线上误框一段红字后，直接改阈值可能同时漏掉浅色印章。先解释错误类型再决定怎么修。

本文使用2018 年固定 Darknet 提交、YOLOv3 与独立文档数据划分。继续研究检测模型时，先保证数据定义、预处理和评估口径稳定。文中方法和预期不代表已经获得某个准确率或部署成绩，真实结论必须来自记录完整的实验。

## 1. 从现象推到机制

难负样本应保留来源与模型版本，人工确认它确实不属于目标。数据回流经过脱敏、去重与标注复核后进入训练候选，不自动加入独立测试集。修复验证需要保留原失败与相邻正常情况。

图中的四个节点分别表示失败证据、人工复核、候选数据、独立验证。顺着实线检查输入如何变成输出，再沿虚线核对反馈条件。图示表达的是本文讨论的关系，不是实测曲线或现场截图。

## 2. 最小实现与输入条件

将误检按红字、表格、图标和噪声分类，先少量复核。比较补数据、预处理与阈值三类方案，避免同时改动所有条件。

```text
failure -> source and model identity
review -> true error category
sanitize and deduplicate -> training candidate
update -> evaluate old failures plus fixed independent set
```

每次只改变一组关键因素，保存配置、权重、数据清单与输出。训练、验证和测试职责分离，难例分析保留匿名原始证据，不通过删除失败样本改善表面指标。

## 3. 用对照区分原因

下表列出需要主动改变的条件。预期行为来自机制分析，复现时还需记录运行环境和原始输出，不能将预期当作已经测得的结果。

| 改变的条件 | 需要验证的行为 |
| --- | --- |
| 误检其实是漏标真目标 | 先修数据而非强化负样本 |
| 同一原件多次回流 | 不能把重复当成新多样性 |
| 只修好旧失败样本 | 还需检查其他类别退化 |

### 对照 1：误检其实是漏标真目标

先修数据而非强化负样本。观察时记录人工复核与原标注。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 2：同一原件多次回流

不能把重复当成新多样性。观察时记录原件身份与近重复检查。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 3：只修好旧失败样本

还需检查其他类别退化。观察时记录固定独立集与正常对照。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。

## 4. 适用条件与取舍

真实文档回流必须有适当授权和脱敏。公开文章使用合成例子，不以调试为由保存无关个人信息。

一次正常运行只覆盖了这组输入。继续扩展前，应把上面的异常对照保留下来，尤其关注“只修好旧失败样本”这一分支。后续方案若改变了图中任意一处依赖，原来的判断就要重新验证，不能仅凭界面相似或返回值相同沿用结论。
