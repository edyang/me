红色印章很醒目，可以先做简单视觉基线，但不能据此认定颜色分割足够处理所有文档。

本文使用合成文档图、YOLO 标注格式与 OpenCV 3.4。文档标题与印章定位先是数据定义问题，再是模型问题。框代表什么、哪些情况不标以及如何处理多页，都会改变训练目标和评估含义。

## 1. 从现象推到机制

HSV（色相饱和度明度）分割可提取部分红色区域，红色环绕色相边界时需考虑两段区间。扫描偏色、浅印、黑白复印和红色文字都会影响结果。轮廓面积与形状只提供候选约束。

![印章检测研究：先建立颜色与轮廓基线的处理、反馈与观察关系](/img/tech-notes/stamp-color-segmentation-baseline.svg)

图中的四个节点分别表示原始文档、颜色掩码、轮廓筛选、难例比较。顺着实线检查输入如何变成输出，再沿虚线核对反馈条件。图示表达的是本文讨论的关系，不是实测曲线或现场截图。

## 2. 最小实现与输入条件

在合成页上比较原图、掩码和轮廓框，单独准备红字、浅色印章与灰度页。阈值根据数据验证，不使用通用常数承诺效果。

```python
hsv = cv2.cvtColor(image, cv2.COLOR_BGR2HSV)
mask1 = cv2.inRange(hsv, lower_red_1, upper_red_1)
mask2 = cv2.inRange(hsv, lower_red_2, upper_red_2)
mask = cv2.bitwise_or(mask1, mask2)
# 阈值需要由演示数据校验后提供
```

先建立少量人工可复核的合成样本，保留原图、标注和处理版本。按文档来源或模板拆分集合，禁止同一原件的不同裁剪分别进入训练与测试形成泄漏。

## 3. 用对照区分原因

下表列出需要主动改变的条件。预期行为来自机制分析，复现时还需记录运行环境和原始输出，不能将预期当作已经测得的结果。

| 改变的条件 | 需要验证的行为 |
| --- | --- |
| 只有红色正文没有印章 | 颜色区域不应直接等同印章 |
| 灰度复印仍有印章 | 颜色基线可能完全失效 |
| 浅印导致区域断裂 | 形态学会改变候选边界 |

### 对照 1：只有红色正文没有印章

颜色区域不应直接等同印章。观察时记录候选形状与人工类别。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 2：灰度复印仍有印章

颜色基线可能完全失效。观察时记录测试来源与成像方式。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 3：浅印导致区域断裂

形态学会改变候选边界。观察时记录处理前后掩码和目标完整性。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。

## 4. 适用条件与取舍

基线价值在于说明可用条件和难例，不是替代学习模型。两种方案应在同一独立数据上按相同口径比较。

一次正常运行只覆盖了这组输入。继续扩展前，应把上面的异常对照保留下来，尤其关注“浅印导致区域断裂”这一分支。后续方案若改变了图中任意一处依赖，原来的判断就要重新验证，不能仅凭界面相似或返回值相同沿用结论。
