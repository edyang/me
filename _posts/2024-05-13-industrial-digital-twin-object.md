三维展示和实时数据放一起，不证明对象关系正确。台账和运行状态需要独立身份。

对象模型关联位置、属性、来源与生命周期，实时观测具有有效期，历史归档保留变化。不同系统 ID 通过受控映射统一。

![数字孪生对象：设备台账、实时状态与历史：处理路径与验证条件](/img/tech-notes/industrial-digital-twin-object.svg)

## 一、问题的范围与前提

数据类型、单位、身份、时间与质量构成一份完整观测。传输格式相同不说明物理含义相同，接收成功也不说明数据新鲜。聚合与展示是派生层，应能回到输入范围与转换规则。

## 二、技术分析与方案取舍

同一设备在资产系统、地图和采集网关可能有不同ID，受控映射让观测归属稳定对象。位置与型号属于台账，运行值带时间质量，历史变化另存。三维动画反映已有状态而不是创造事实，缺数据时明确未知。对象替换、退役和位置更新后，检查旧观测和告警不会挂到新设备。

建立测点和字段字典，明确空值、错误码、复位和晚到数据的处理。数值计算由确定性程序完成，保留版本和必要输入；文本解释只描述实际计算结果。按统计对象和时间窗口组织数据，避免不同分母或单位被放到同一比较中。

## 三、实现与排查的顺序

1. 建立对象字典。
2. 关联来源和空间。
3. 管理实时历史。
4. 校验对象更新。

按这个顺序保留中间结果，可以区分输入条件、处理过程和最终输出。前一阶段的条件不成立时，先解释对应错误，再继续后面的试验；单次返回成功不足以覆盖整条链路。

### 最小示例

```json
{"schema_version": 1, "event_id": "example-001", "status": "pending", "payload": {}}
```

JSON 只是结构示意，后续需验证枚举、类型、对象与权限。事件 ID 不包含客户身份，版本只表达协议；合法解析不能代替事实与业务校验。

## 四、验证和结果解释

样本核验覆盖边界、缺测、重复和异常范围，保存被排除数据的理由。图表与正文引用相同版本，公式改变后对应结果也更新。高频采样不自动拥有更大业务权重，统计方法应符合物理量与任务目标。

| 需要验证的结果 | 保留的对照 | 不能由此推出的结论 |
| --- | --- | --- |
| 同设备不重复 | 固定输入与配置、对应输出 | 一次成功代表所有条件成功 |
| 旧值有标记 | 中断前后状态与错误阶段 | 没有报错代表结果正确 |
| 历史可回放 | 恢复后的同条件复测 | 临时恢复代表根因已经消失 |

验证导入失败、晚到补传、重复记录和配置修订。系统不应把无效数据默默转换成正常零值，也不为了曲线好看隐藏缺失。涉及真实人员或业务敏感资料时，示例只保留脱敏结构，不公开原始附件。

## 五、适用边界与结论

展示效果不是模型完整性证明，缺失对象关系不能由动画补齐。

这条路径把“建立对象字典”与“校验对象更新”连在一起，中间保留可复查的条件。实施时优先确认“同设备不重复”，再检查“历史可回放”；两者都满足，才能在当前样本与配置范围内评价方案。设备、数据或软件版本改变以后，相关假设需要重新验证。
