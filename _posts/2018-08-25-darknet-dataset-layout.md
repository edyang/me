训练能开始但效果异常，先检查数据文件关系，而不是立即修改网络结构。

本文使用原版 Darknet 固定历史提交、YOLOv2/YOLOv3 与演示图片。目标检测回答对象类别与位置，不自动识别全部文字或判断印章真伪。文中的训练与部署方案属于可复现方法，没有给出未经测试的准确率、速度或客户验收成绩。

## 1. 从现象推到机制

data 文件指定类别数、训练列表、验证列表与类别名称。每张图对应的标注需要在正确位置，类别编号从零开始并保持稳定。路径可读和图片可解码是两回事，空标注也应有明确含义。

![Darknet 自定义数据：路径、类别与标注一一对应的处理、反馈与观察关系](/img/tech-notes/darknet-dataset-layout.svg)

图中的四个节点分别表示数据清单、类别定义、逐图标注、可视复核。顺着实线检查输入如何变成输出，再沿虚线核对反馈条件。图示表达的是本文讨论的关系，不是实测曲线或现场截图。

## 2. 最小实现与输入条件

建立只有 title 与 seal 两类的合成数据集，逐张叠加标注复核。列表中不混入客户真实文档和测试集。

```text
doc.data: classes=2, train=..., valid=..., names=...
doc.names: title / seal
image: page_001.jpg
label: page_001.txt
label row: class_id x_center y_center width height
```

先保存源码提交、构建选项、配置、权重和输入图片，再对照原始输出。图片只用合成文档或已获授权数据，真实文档中的姓名、编号和印章图样不进入公开训练素材。

## 3. 用对照区分原因

下表列出需要主动改变的条件。预期行为来自机制分析，复现时还需记录运行环境和原始输出，不能将预期当作已经测得的结果。

| 改变的条件 | 需要验证的行为 |
| --- | --- |
| 类别名称顺序被交换 | 编号含义会跟着错位 |
| 文件存在但图片损坏 | 训练读取仍会失败 |
| 训练验证列表有同一原件 | 评估可能产生泄漏 |

### 对照 1：类别名称顺序被交换

编号含义会跟着错位。观察时记录names 与标注类别 id。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 2：文件存在但图片损坏

训练读取仍会失败。观察时记录完整解码而非只检查后缀。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 3：训练验证列表有同一原件

评估可能产生泄漏。观察时记录原始文档身份与拆分清单。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。

## 4. 适用条件与取舍

数据检查应先于长时间训练。先发现标注偏移与类别错配，通常比在错误数据上调学习率更有价值。

一次正常运行只覆盖了这组输入。继续扩展前，应把上面的异常对照保留下来，尤其关注“训练验证列表有同一原件”这一分支。后续方案若改变了图中任意一处依赖，原来的判断就要重新验证，不能仅凭界面相似或返回值相同沿用结论。
