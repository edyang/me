不规则上传按行平均，可能给高频区间更大权重。统计需先明确目标和时间权重。

事件时间与接收时间分桶不同，晚到记录会改变历史窗口。去重在聚合前执行，边界用一致闭开规则。

![时序聚合：窗口边界与晚到数据：处理路径与验证条件](/img/tech-notes/sql-time-bucket.svg)

## 一、问题的范围与前提

数据类型、单位、身份、时间与质量构成一份完整观测。传输格式相同不说明物理含义相同，接收成功也不说明数据新鲜。聚合与展示是派生层，应能回到输入范围与转换规则。

## 二、技术分析与方案取舍

窗口通常采用开始包含、结束不包含，以避免整点记录进入两组；跨日与时区转换需要同一规则。不规则采样如果统计持续状态，可以按时间权重，而不是每行同权。晚到数据按业务时间修改历史窗口，重算范围受控。清洗与统计保留原始身份，重复补传先去重再聚合。

建立测点和字段字典，明确空值、错误码、复位和晚到数据的处理。数值计算由确定性程序完成，保留版本和必要输入；文本解释只描述实际计算结果。按统计对象和时间窗口组织数据，避免不同分母或单位被放到同一比较中。

## 三、实现与排查的顺序

1. 选定统计时间。
2. 固定窗口和时区。
3. 先去重再计算。
4. 受控重算晚到窗口。

按这个顺序保留中间结果，可以区分输入条件、处理过程和最终输出。前一阶段的条件不成立时，先解释对应错误，再继续后面的试验；单次返回成功不足以覆盖整条链路。

### 最小示例

```python
import time
from datetime import datetime, timezone

observed_at = datetime.now(timezone.utc).isoformat()
started = time.monotonic()
# 在这里执行待测操作
elapsed = time.monotonic() - started
```

UTC 时间用于表达绝对时刻，单调时钟用于本机耗时，二者不能互换。示例操作为空，因此不提供任何业务性能数字。设备时间、接收时间与显示时区仍需各自保留语义。

示例聚焦当前技术关系。引用的图片、数据库、消息对象或处理函数，需要由调用环境提供；它不包含完整服务的认证、持久化与并发管理。验证时先用受控输入检查，再纳入应用。

## 四、验证和结果解释

样本核验覆盖边界、缺测、重复和异常范围，保存被排除数据的理由。图表与正文引用相同版本，公式改变后对应结果也更新。高频采样不自动拥有更大业务权重，统计方法应符合物理量与任务目标。

| 需要验证的结果 | 保留的对照 | 不能由此推出的结论 |
| --- | --- | --- |
| 跨日不重复 | 固定输入与配置、对应输出 | 一次成功代表所有条件成功 |
| 采样频率不改变定义 | 中断前后状态与错误阶段 | 没有报错代表结果正确 |
| 补传更新可解释 | 恢复后的同条件复测 | 临时恢复代表根因已经消失 |

验证导入失败、晚到补传、重复记录和配置修订。系统不应把无效数据默默转换成正常零值，也不为了曲线好看隐藏缺失。涉及真实人员或业务敏感资料时，示例只保留脱敏结构，不公开原始附件。

## 五、适用边界与结论

状态量和累计量不能套相同平均，插值应显式说明，不能用平滑掩盖缺测。

这条路径把“选定统计时间”与“受控重算晚到窗口”连在一起，中间保留可复查的条件。实施时优先确认“跨日不重复”，再检查“补传更新可解释”；两者都满足，才能在当前样本与配置范围内评价方案。设备、数据或软件版本改变以后，相关假设需要重新验证。
