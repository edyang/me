RGB 直接筛颜色受亮度变化影响，转换 HSV 可分开部分色调与亮度条件，但仍需检验曝光和白平衡。

色调在低饱和区域不稳定，红色还涉及范围环绕。OpenCV 不同数据类型的数值范围需要核对，不能复制其它库的门限。

![颜色空间分割：HSV 范围和亮度变化：处理路径与验证条件](/img/tech-notes/opencv-color-space-mask.svg)

## 一、问题的范围与前提

成像质量、数据分布、算法与业务判断各自有条件。清晰图像提供可观察细节，模型和规则解释输入，业务层决定结果如何使用。视野、曝光、颜色、姿态与输入尺度变化，都可能在模型参数不变时改变结果。

## 二、技术分析与方案取舍

OpenCV 的 HSV 在不同输入类型中范围可能不同，门限要与实际数组匹配。接近灰色区域饱和度低，色调不稳定；红色跨越色调环绕边界，可能要组合两个范围。曝光与白平衡变化也会移动颜色分布。固定相机条件并收集允许工况，再评价遮挡、高光和暗部，不把一组门限当所有场景标准。

先固定输入和处理版本，保存必要中间产物，再比较单项变化。裁剪、缩放和配准要携带坐标关系，输出回到原图时检查尺度与偏移。数据按正常和困难条件分别组织，不把反光、遮挡或采集失败从报告中悄悄删掉。

## 三、实现与排查的顺序

1. 固定输入类型。
2. 采集允许光照范围。
3. 分别约束色调饱和亮度。
4. 保留失败掩膜分析。

按这个顺序保留中间结果，可以区分输入条件、处理过程和最终输出。前一阶段的条件不成立时，先解释对应错误，再继续后面的试验；单次返回成功不足以覆盖整条链路。

### 最小示例

```python
import cv2

image = cv2.imread("example.png", cv2.IMREAD_GRAYSCALE)
if image is None:
    raise ValueError("image not found")
_, mask = cv2.threshold(image, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
```

示例使用全局 Otsu 阈值，输入需真实存在。它不保证不均匀照明或任何材质效果，形态学与候选筛选应保留独立对照。

示例聚焦当前技术关系。引用的图片、数据库、消息对象或处理函数，需要由调用环境提供；它不包含完整服务的认证、持久化与并发管理。验证时先用受控输入检查，再纳入应用。

## 四、验证和结果解释

独立样本应覆盖预期工况，逐条预测与错误图支持复盘。分类、检测、定位和异常任务使用各自指标定义，阈值工作点与曲线指标不能混用。性能同时记录冷启动、稳态、尾部耗时和资源峰值，不挑最快一张代表整套系统。

| 需要验证的结果 | 保留的对照 | 不能由此推出的结论 |
| --- | --- | --- |
| 暗部高光不会误选 | 固定输入与配置、对应输出 | 一次成功代表所有条件成功 |
| 数值范围符合实现 | 中断前后状态与错误阶段 | 没有报错代表结果正确 |
| 尺度变化不改变语义 | 恢复后的同条件复测 | 临时恢复代表根因已经消失 |

验证无目标、多候选、边界、遮挡和不同光照。没有有效观测时给出明确失败或待确认，不为每张图强行选一个目标。图像文件真实保存和完整解码也属于链路检查，热力图漂亮不能替代缺陷真值与业务验收。

## 五、适用边界与结论

HSV 不是所有材质的稳健解决方案，自动曝光和白平衡可能仍需约束。

这条路径把“固定输入类型”与“保留失败掩膜分析”连在一起，中间保留可复查的条件。实施时优先确认“暗部高光不会误选”，再检查“尺度变化不改变语义”；两者都满足，才能在当前样本与配置范围内评价方案。设备、数据或软件版本改变以后，相关假设需要重新验证。
