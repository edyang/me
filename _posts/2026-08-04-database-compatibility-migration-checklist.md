数据库迁移或兼容适配中，应用连接成功只是最开始的一步。原有 SQL、数据类型和事务假设，都可能在新数据库上产生不同结果。

## 把差异按用途整理

| 项目 | 需要检查的内容 |
| --- | --- |
| 数据类型 | 精度、空值、时间、布尔值与大字段 |
| SQL | 分页、函数、序列、关键字与方言 |
| 事务 | 隔离级别、锁、并发与异常回滚 |
| 结构 | 索引、约束、存储过程与触发器 |
| 数据迁移 | 总量、抽样、关联、编码与边界值 |

ORM 可以减少部分方言差异，但原生 SQL、批量写入和历史脚本仍需逐条检查。不能因为核心页面能查询，就认为全部业务已经兼容。

## 验证要覆盖完整业务动作

选择真实业务的读写链路，比较迁移前后的结果、约束和性能。关键计算需要固定输入和预期输出；并发写入要验证事务边界，而不是只跑单线程演示。

## 为切换保留回退条件

记录迁移批次、数据校验和切换时刻，明确是否允许并行写入以及回退时的数据处理。正式切换前先做一次完整演练，验证恢复方法。
