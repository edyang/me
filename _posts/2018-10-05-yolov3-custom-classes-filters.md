把类别数改成两类，却只修改一个检测头，会让配置与权重维度不一致。

本文使用原版 Darknet 固定历史提交、YOLOv2/YOLOv3 与演示图片。目标检测回答对象类别与位置，不自动识别全部文字或判断印章真伪。文中的训练与部署方案属于可复现方法，没有给出未经测试的准确率、速度或客户验收成绩。

## 1. 从现象推到机制

原版 YOLOv3 在多个尺度输出检测，检测层类别数与前面卷积通道数需要匹配。每个头使用三个锚框时，filters 为三乘类别数加五的和。掩码和锚框数量变化后，不能继续机械使用同一公式。

图中的四个节点分别表示类别清单、检测尺度、通道匹配、加载核对。顺着实线检查输入如何变成输出，再沿虚线核对反馈条件。图示表达的是本文讨论的关系，不是实测曲线或现场截图。

## 2. 最小实现与输入条件

复制固定源码中的配置，逐个检查三个检测层及其前置卷积。两类、每头三个锚框的演示配置对应二十一通道。

```ini
# 每个检测头分别检查
[convolutional]
filters=21
# ... 对应输出卷积 ...
[yolo]
classes=2
# 21 = 3 * (2 + 5)
```

先保存源码提交、构建选项、配置、权重和输入图片，再对照原始输出。图片只用合成文档或已获授权数据，真实文档中的姓名、编号和印章图样不进入公开训练素材。

## 3. 用对照区分原因

下表列出需要主动改变的条件。预期行为来自机制分析，复现时还需记录运行环境和原始输出，不能将预期当作已经测得的结果。

| 改变的条件 | 需要验证的行为 |
| --- | --- |
| 只改一个头的 classes | 不同尺度输出语义会不一致 |
| 类别从两类增加 | 所有相关输出维度都需更新 |
| 使用不同数量锚框 | 需按每头实际锚框数量重算 |

### 对照 1：只改一个头的 classes

不同尺度输出语义会不一致。观察时记录全部检测层与前置卷积。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 2：类别从两类增加

所有相关输出维度都需更新。观察时记录names 标注与网络配置。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 3：使用不同数量锚框

需按每头实际锚框数量重算。观察时记录mask 与输出通道关系。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。

## 4. 适用条件与取舍

配置能加载只是结构一致，不说明数据和任务合理。训练前先用少量样本核对标注与输出，避免长时间运行后才发现类别错位。

一次正常运行只覆盖了这组输入。继续扩展前，应把上面的异常对照保留下来，尤其关注“使用不同数量锚框”这一分支。后续方案若改变了图中任意一处依赖，原来的判断就要重新验证，不能仅凭界面相似或返回值相同沿用结论。
