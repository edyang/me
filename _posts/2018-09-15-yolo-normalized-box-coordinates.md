框在标注工具里正确，训练图上却偏移，常见原因是坐标基准、缩放或宽高换算错误。

本文使用合成文档图、YOLO 标注格式与 OpenCV 3.4。文档标题与印章定位先是数据定义问题，再是模型问题。框代表什么、哪些情况不标以及如何处理多页，都会改变训练目标和评估含义。

## 1. 从现象推到机制

YOLO 标注使用归一化中心点与宽高，需要除以对应原图尺寸。先裁剪再标与先标后缩放要保留不同变换关系。超出边界的框应按明确规则处理，不直接截断到看起来合理。

![文档标注：像素框怎样正确转成 YOLO 坐标的处理、反馈与观察关系](/img/tech-notes/yolo-normalized-box-coordinates.svg)

图中的四个节点分别表示像素边界、中心宽高、归一化、反向叠加。顺着实线检查输入如何变成输出，再沿虚线核对反馈条件。图示表达的是本文讨论的关系，不是实测曲线或现场截图。

## 2. 最小实现与输入条件

用一张已知宽高的合成页做正向与反向换算，叠加后应回到同一位置。所有数据变换保留尺寸与偏移。

```python
xc = ((xmin + xmax) / 2.0) / image_width
yc = ((ymin + ymax) / 2.0) / image_height
w = (xmax - xmin) / float(image_width)
h = (ymax - ymin) / float(image_height)
```

先建立少量人工可复核的合成样本，保留原图、标注和处理版本。按文档来源或模板拆分集合，禁止同一原件的不同裁剪分别进入训练与测试形成泄漏。

## 3. 用对照区分原因

下表列出需要主动改变的条件。预期行为来自机制分析，复现时还需记录运行环境和原始输出，不能将预期当作已经测得的结果。

| 改变的条件 | 需要验证的行为 |
| --- | --- |
| 把左上角当中心点 | 训练框会发生系统性偏移 |
| 横纵归一化分母写反 | 非正方形页面更容易暴露错误 |
| 图片裁剪后沿用旧标签 | 需要同时变换框坐标 |

### 对照 1：把左上角当中心点

训练框会发生系统性偏移。观察时记录正反转换后的叠加位置。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 2：横纵归一化分母写反

非正方形页面更容易暴露错误。观察时记录原图宽高与各轴比例。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 3：图片裁剪后沿用旧标签

需要同时变换框坐标。观察时记录裁剪原点与缩放记录。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。

## 4. 适用条件与取舍

边界约定还需统一像素端点是否包含最后一列。小目标对一两个像素更敏感，转换工具应有可视化复核。

一次正常运行只覆盖了这组输入。继续扩展前，应把上面的异常对照保留下来，尤其关注“图片裁剪后沿用旧标签”这一分支。后续方案若改变了图中任意一处依赖，原来的判断就要重新验证，不能仅凭界面相似或返回值相同沿用结论。
