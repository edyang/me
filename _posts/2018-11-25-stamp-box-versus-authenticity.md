检测器给出 seal 框，最多说明模型认为那里像训练中的印章区域，不能据此判定文件有效。

本文使用合成文档图、YOLO 标注格式与 OpenCV 3.4。文档标题与印章定位先是数据定义问题，再是模型问题。框代表什么、哪些情况不标以及如何处理多页，都会改变训练目标和评估含义。

## 1. 从现象推到机制

定位模型依据像素模式输出类别与位置，真伪核验还需要可信样本、来源与专门规则。压缩、缩放和扫描都会改变外观。单凭相似度或红色轮廓，不足以证明用印行为与文档身份。

![印章检测应用：找到印章与验证真伪是两项任务的处理、反馈与观察关系](/img/tech-notes/stamp-box-versus-authenticity.svg)

图中的四个节点分别表示检测任务、候选输出、后续处理、结论边界。顺着实线检查输入如何变成输出，再沿虚线核对反馈条件。图示表达的是本文讨论的关系，不是实测曲线或现场截图。

## 2. 最小实现与输入条件

把系统输出限定为候选区域、置信度和模型版本，供后续 OCR 或人工审阅。界面不显示“真章已验证”这类越界结论。

```json
{"class":"seal","box":[120,300,220,400],
 "score":0.82,"model_version":"demo-v1",
 "meaning":"candidate_region_only"}
```

先建立少量人工可复核的合成样本，保留原图、标注和处理版本。按文档来源或模板拆分集合，禁止同一原件的不同裁剪分别进入训练与测试形成泄漏。

## 3. 用对照区分原因

下表列出需要主动改变的条件。预期行为来自机制分析，复现时还需记录运行环境和原始输出，不能将预期当作已经测得的结果。

| 改变的条件 | 需要验证的行为 |
| --- | --- |
| 预测分数很高 | 仍不能直接表达真伪概率 |
| 印章区域能被准确裁出 | 只是后续核验输入准备 |
| 图像经压缩或复印 | 外观相似不能证明原件来源 |

### 对照 1：预测分数很高

仍不能直接表达真伪概率。观察时记录模型任务与评分含义。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 2：印章区域能被准确裁出

只是后续核验输入准备。观察时记录定位与真实性证据分别记录。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。
### 对照 3：图像经压缩或复印

外观相似不能证明原件来源。观察时记录输入链路与已知处理过程。把这个条件与基准情形分开，有助于判断变化来自哪一层；若得到相反结果，应先核对前提，再修改实现。

## 4. 适用条件与取舍

把能力边界写进接口和页面，能避免业务误用。需要真实性判断时，另行制定证据与审核流程，不把模型定位结果升级为法律结论。

一次正常运行只覆盖了这组输入。继续扩展前，应把上面的异常对照保留下来，尤其关注“图像经压缩或复印”这一分支。后续方案若改变了图中任意一处依赖，原来的判断就要重新验证，不能仅凭界面相似或返回值相同沿用结论。
